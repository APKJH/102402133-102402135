## 功能范围

本程序在第一次作业的原型基础上实现了校园失物招领的核心闭环：

1. 首页浏览最新寻物、招领信息，并显示总数、待处理数和已归还数。
2. 按物品名称、类别、地点和描述搜索，支持寻物/招领类型筛选。
3. 查看信息详情并展示联系发布者提示。
4. 发布信息，提交前校验名称、地点、时间和详细描述。
5. 在“我的发布”中查看自己发布的信息，支持修改和删除。
6. 将信息状态更新为“待处理”“已找到”或“已归还”。
7. 使用浏览器 `localStorage` 保存演示数据，刷新页面后数据仍保留。

## 运行方式

### 直接运行

用 Chrome 或 Edge 打开 `index.html` 即可运行。推荐使用浏览器的无痕窗口检查初始数据；新增和修改的数据会保存在当前浏览器的 `localStorage` 中。

### 使用本地静态服务器

在项目根目录执行任意静态服务器，例如：

```text
npx serve .
```

然后按照终端给出的地址访问 `index.html`。

## 单元测试

环境要求：Node.js 18 或更高版本。项目不依赖第三方测试框架，直接执行：

```text
npm test
```

当前测试覆盖关键词搜索、类型筛选、状态筛选、无结果、表单校验、新建、修改、状态更新、时间格式化和统计等 13 个场景，结果为 **13/13 通过**。详细说明见 [`docs/test-report.md`](docs/test-report.md)。

## 设计取舍与限制

本次作业优先实现可运行的核心闭环，未实现后台管理、真实账号认证、实时聊天、地图定位和真实图片上传。联系按钮用提示框模拟，后续接入后端接口即可替换为真实通信功能。业务逻辑集中在 `src/domain.js`，便于后续继续补充接口或自动化测试。
